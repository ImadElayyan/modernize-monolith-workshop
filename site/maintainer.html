Maintain the focused student site

The site includes only setup, Module 2B and selected Module 3 exercises. Original sample applications and guides remain unchanged.

Build and preview locally

Use Python 3.12 or newer. There are no Python or JavaScript package dependencies. From the repository root:

python site\build.py
python -m http.server 8769 --bind 127.0.0.1 --directory _site

Open http://127.0.0.1:8769/. The build recreates only _site, copies the selected screenshots and MIT license, and checks all generated local links and fragment IDs. Do not edit generated HTML.

Content and presentation

Edit the landing page and six guide fragments in site\content. Shared layout, styles and behavior live in template.html, styles.css and site.js. Add any new local screenshot to the explicit map in build.py. Nothing outside that map is published.

The user-selected visual theme follows the Copilot Dev Days Java workshop: dark grid, cyan/magenta accents, Space Grotesk and JetBrains Mono, landing cards and a step sidebar. Fonts load from Google Fonts with local system fallbacks. No analytics or external JavaScript is loaded. The default is dark; the theme switch carries the selection through page links.

Do not label proposed pacing as an upstream duration, promise successful agent runs, or claim the fallback starter completes a student's upgrade. Verify changing tooling requirements against Microsoft Learn.

Publish after approval

  1. Review the generated site and the repository diff before publishing.
  2. Push the reviewed branch and merge its changes into main only after approval.
  3. In the fork's Settings > Pages, choose GitHub Actions as the source. Forked repositories may also require Actions to be enabled.
  4. Run Student workshop Pages from the Actions tab on main, or allow its push trigger to run.
  5. Wait for deployment to succeed and open the URL shown by the deployment. The expected default URL is https://imadelayyan.github.io/modernize-monolith-workshop/; do not announce it as live until the deployment succeeds.

Pull requests build the site without deployment. Only main may deploy. The workflow uploads _site, not the complete repository or the unselected modules. This publishing guide is not part of the generated student site.

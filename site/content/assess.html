Make the migration explicit before you execute it. This is the assessment and planning stage of Module 2B.

Input: working .NET Framework 4.8 appOutput: reviewed migration plan

1. Open the modernization agent

Open your isolated eShopLiteFx.sln in Visual Studio. Right-click the solution/project and select Modernize, or open Copilot Chat and enter @Modernize. Choose the .NET upgrade path if the installed version offers it.

2. Request assessment before code changes

Use guided interaction and review proposed actions. The upstream guide demonstrates Autopilot, but this student route keeps the plan review explicit.

Assess this eShopLite solution for migration from .NET Framework 4.8
to .NET 10. Work in this isolated application repository.

Before changing application code:
- Identify project types, NuGet packages and framework-specific APIs.
- Inspect the current MVC frontend and database configuration.
- Identify risks in moving EF6 and SQL Server LocalDB to EF Core and SQLite.
- Identify the work needed to convert the UI to Blazor.
- Produce an assessment and a staged upgrade plan.
- Include build and behavior checks after each meaningful stage.

Keep the application local. Do not provision Azure resources, introduce
microservices, or add Aspire, Redis or AI features.
Stop after the plan and wait for my review.
Expected result

A repository-specific assessment and staged plan describing the .NET 10 upgrade, dependencies and risks. The agent may create planning files. There is no fixed filename, response text or runtime that every student should expect.

3. Review and refine the generated plan

Open the generated plan in the editor. Confirm it covers all of the following; if it does not, add the missing requirements or ask Copilot to revise it:

  • Runtime: .NET 10 and an appropriate SDK-style project structure.
  • Database: SQLite with compatible EF Core packages, schema and seed data; preserve the behavior of the sample application.
  • Frontend: Blazor components with working routing, layouts and static assets.
  • Dependencies: replacements for unsupported APIs and packages, with explanations of breaking changes.
  • Checkpoints: build, run, inspect pages and data, review the diff, then commit.

4. Approve a bounded first stage

The plan is reviewed. Start with the framework and package upgrade.
Keep the .NET 10 target and the agreed local-only scope.
Show the changes and build results before moving to database or UI work.
If a step fails, explain the error and proposed fix instead of hiding it.
Do not approve commands blindly.

Read requests that install packages, run scripts, remove files or change Git history. Never paste production connection strings, credentials or customer data into this sample exercise.

Lab 1 complete when

You can explain the baseline, the three target changes and the validation plan. You have reviewed the plan and know which stage you approved next.

2. Assess what actually remains

Open the chosen solution. Start Modernize in Visual Studio or enter @Modernize in Copilot Chat, and request a reviewed plan:

This application targets .NET 10. Assess its current implementation
before changing anything.

Identify remaining modernization opportunities:
- Database provider, persistence and seed-data behavior.
- Dependency injection and service boundaries.
- Async data access and appropriate routing.
- Namespaces and package/API compatibility.
- Newtonsoft.Json usage and serialization behavior.
- Remaining MVC pages versus completed Blazor components.

Distinguish work already completed from work still needed.
Propose small, testable changes. Keep everything local.
Do not add microservices, Aspire, Redis, Azure deployment or AI features.
Pause for my review before applying changes.

4. Repeat the review loop

  1. Review the proposed change and its expected impact.
  2. Approve a bounded implementation and inspect the diff.
  3. Build the solution and run any relevant tests that exist. If there are no tests, do not claim a passing automated test suite.
  4. Manually exercise the affected pages, data and navigation. Compare with the baseline.
  5. Commit a working checkpoint. Continue only if there is time for another complete review loop.
Missing images, blank pages or proxy errors

Check static-file paths, routing, layouts and startup logs. Ask Copilot to diagnose the actual error. Do not remove a proxy or dependency just because a generic troubleshooting example mentions it; establish whether the chosen application needs it.

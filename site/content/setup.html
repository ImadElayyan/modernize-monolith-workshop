Prepare the Windows toolchain and establish a working baseline before asking Copilot to change anything.

No Azure account, cloud resources or Docker required for this focused route.

The original .NET Framework web app needs Windows and Visual Studio's web build tools. A Linux Codespace is not a drop-in replacement for this starting point.

1. Install the prerequisites

Checkboxes are a convenience for this page visit; they are not submitted or saved.

Current Microsoft installation guidance supports paid or free Copilot and also lists VS 2022 17.14.17+ for the upgrade tooling. Tool availability does not by itself establish full .NET 10 IDE support; standardize on VS 2026 for this workshop. Organization policy and usage limits still apply. The upstream workshop recommends Copilot Pro.

Useful downloads: Visual Studio, .NET 10, .NET Framework 4.8 developer pack, Git.

2. Check the local tools

Open PowerShell and run:

git --version
dotnet --list-sdks
sqllocaldb info
Expected result

Git reports its version; the SDK list includes a 10.0.x entry. LocalDB is installed and the MSSQLLocalDB instance is available. If LocalDB is missing, use Microsoft's LocalDB setup guide before continuing.

3. Get an isolated copy of the legacy app

Use fresh folders. The repository copy is your reference; Copilot will work in a separate Git repository containing only the starter application. This follows the upstream warning to copy StartSample elsewhere, rather than letting the agent modify the complete workshop repository.

Run this in PowerShell. If the paths already exist, choose new names; do not overwrite earlier lab work.

$ErrorActionPreference = 'Stop'
$labs = Join-Path $HOME 'CopilotLabs'
$reference = Join-Path $labs 'modernize-monolith-workshop'
$working = Join-Path $labs 'eshoplite-upgrade'
if ((Test-Path $reference) -or (Test-Path $working)) {
    throw 'Choose new reference and working folder names before continuing.'
}
New-Item -ItemType Directory -Force -Path $labs | Out-Null
git clone https://github.com/ImadElayyan/modernize-monolith-workshop.git $reference
if ($LASTEXITCODE -ne 0) { throw 'Clone failed. Resolve the error before continuing.' }
$starter = Join-Path $reference '2-upgrade-dotnet\2-upgrade-with-ghcp-modernization-app\StartSample'
Copy-Item -Recurse -Path $starter -Destination $working
Copy-Item (Join-Path $reference '.gitignore') (Join-Path $working '.gitignore')
Copy-Item (Join-Path $reference 'LICENSE.md') (Join-Path $working 'LICENSE.md')
Set-Location $working
git init
if ($LASTEXITCODE -ne 0) { throw 'Git initialization failed.' }
git status --short

Review the listed files. After confirming there are no secrets or generated build artifacts, commit the baseline:

git add .
git commit -m "Save original eShopLite starter"
git switch -c student/modernization

Run the last three commands one at a time and stop if one fails. If Git asks for your identity, configure your own name and email in this local repository, then retry the commit. There is no need to push or publish student changes.

4. Run the original application

  1. In Visual Studio, open eshoplite-upgrade\eShopLiteFx.sln from your working folder.
  2. Restore NuGet packages. Set eShopLite.StoreFx as the startup project if necessary.
  3. Use Build > Build Solution, then run with IIS Express. Do not use dotnet run as the launch instruction for this legacy project.
  4. Check the home page, products, store information and product images. Record a few expected values or take your own screenshots for comparison.
  5. Right-click the solution/project and confirm Modernize appears, or send @Modernize in Copilot Chat.
Missing csc.exe during the legacy build

The upstream guide documents this recovery command. Run it in Visual Studio's NuGet Package Manager Console, with the legacy project selected, not in ordinary PowerShell:

Update-Package Microsoft.CodeDom.Providers.DotNetCompilerPlatform -r

Rebuild and inspect any remaining errors. This is a targeted recovery step, not a guarantee that other failures will disappear.

Database connection fails

The starter's Web.config points at (LocalDb)\MSSQLLocalDB, database eShopLite, using Windows authentication. Confirm the instance exists and can start. SQL Express installed without LocalDB does not satisfy this connection string automatically.

Modernize is missing or Copilot cannot respond

Check the installed optional components, Visual Studio version, GitHub sign-in and your organization's Copilot policy. Restart the IDE after installing components. Follow the current Microsoft installation guide rather than installing the traditional Upgrade Assistant as a substitute.

Ready to proceed

The original app builds and runs, your baseline is committed in an isolated repository, and the modernization agent responds. If any of these fail, resolve them with the instructor before starting Lab 1.
